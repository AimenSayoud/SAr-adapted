# CLAUDE.md

InSAR analysis of the Rzecin floating peatland (Poland): Sentinel-1 C-band with field and auxiliary data in a
data cube (the hub's `06_data/cube/README.md` lists what it holds). **Aim:** methods adapted to the floating mat
that track its vertical displacement. Established: per-pixel inversion fails physically. Provisional (one laser
point so far): the motion shows up in the shortest consecutive pairs and is lost on longer ones; the aggregated
seasonal series of the first study (2022–2024, the manuscript in `docs/paper/`) is not that motion. The hub's
`SETTLED.md` and `STATE.md` hold the current answers; the manuscript is an early attempt, not the reference.

## Commands

8 GB: never propose running those locally.

## Numbers — the rule that matters most

**Never write a number into prose by hand.** Its source of truth is a CSV in
`results/tables/T*.csv` (robustness tables: `results/robustness/`; figure images stay in
`docs/paper/figures/`).

A referee found seven quantities where the text and Appendix B disagreed. Every one came
from a value being typed once and never revisited. `src/insar_wetlands/paper_numbers.py`
exists to prevent recurrence:

- `REGISTRY` maps each load-bearing number to its CSV, column and format.
- `SUPERSEDED` lists dead values (e.g. `−0.069`) that must never reappear.
- `make check` fails if a registered number is absent or a superseded one is present.
- The guard **fails closed**: an entry whose CSV or column cannot be resolved is
  an error, not a skip. A genuinely pending export goes in `PENDING` with a
  reason. Before this, `make check` passed against an empty `figures/`, so
  renaming a column silently unregistered the number it protected.

**When you introduce or change a load-bearing number, add it to `REGISTRY` in the same
change.** One line, permanent protection.

## Recording a run

`python -m insar_wetlands.register run <entry>` (and `make run`) writes one manifest per execution:
- on the Mac, to the hub's `05_code/runs/<entry>/<UTC>_<sha>/manifest.json`;
- on Colab, to Drive `runs/`.

Each manifest holds the commit and whether the tree was dirty, the package versions, the arguments, the duration,
the exit code and every output file written. Phase code that archives heavy products uses
`run_archive.archive_run(...)`, which records `.nc`/`.tif`/`.h5` by path, size and hash rather than copying them.
Runs are never overwritten.

## Everything that runs is declared

`config/register.yaml` holds one entry per historical phase, experiment, pipeline and Colab launcher. Each entry
has kind, status, `runs_on`, code at `code_ref` (`HEAD`, or the tag where removed code lives), command, inputs,
outputs, tickets, chains and tries (ids only).
- **Findings never go in the register:** this repo is public. They live in the hub's tries map, and the hub joins
  both halves into `05_code/REGISTER.md`.
- **Adding a script means adding an entry.** `make register` fails on an undeclared script, a missing code path or a
  malformed id.
- **Never re-run a `superseded` entry.** A `finished` entry's result stands for its scope. Changing what it never
  varied is a new entry, with a ticket and a pre-registration.

## Testing

Every scientific routine has a test that recovers a known answer from simulated data
(EVD phase linking on a sparse network; aggregation recovering a displacement buried under
per-pixel noise; the collapse of a spurious correlation between two annual cycles). **Any
new scientific routine needs one before it is used in the paper.** A routine without a
ground-truth test is not evidence.

## Domain constraints

- **Settled findings, with how far each reaches:** the hub's `SETTLED.md`. Its entries are findings, not bans:
  each says what was tested, how it failed, what was never varied and what would reopen it (hub `DECISIONS.md`
  2026-10-11).
- **Per-pixel inversion on the HyP3 products did not recover the mat** (SBAS, ISBAS, hybrid, WLS, sparse EVD; H1).
  Do not re-run the same estimators on the same product class for another track or epoch — nothing that caused the
  failure would change. A test that changes what was never varied (SLC input, SHP looks, full-covariance phase
  linking, bias correction, temporal unwrapping, another chain) is legitimate when it is scored against the truth
  in advance and its result is recorded, whichever way it goes. New approaches designed for the mat (the fusion
  experiments) are open research.
- Empirical p-values have a floor of 1/(1+N). Always state it when reporting one at the floor.
- Nulls must be **size-matched** to the zone under test. Aggregate noise falls as 1/√N, so a
  larger null understates the floor and manufactures detections.
- Bog breathing is **seasonal**. Fitting a velocity to a periodic signal returns ≈ 0 by
  construction and has no power on the physics.
- The paper's claims are scoped to HyP3 products on this network. Phase linking here is not
  the maximum-likelihood estimator on a true SLC covariance matrix — do not restate it as one.

## Style

- Report what the data show, including refutations. Two pre-registered predictions of the
  authors' own were falsified; that is a feature of the paper and stays in.
- Prefer stating an assumption explicitly over quietly relying on it.
- Commit messages say **why**, not what: "Correct the seasonal p-value after the null was
  size-matched", not "update".
- Do not add dependencies without asking. The stack is numpy / pandas / scipy / xarray /
  scikit-learn and stays small.
